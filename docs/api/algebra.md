# `discretus.algebra`

The algebra package builds structures from their axioms upward. It provides
groups and group actions, rings and ideals, fields including finite fields,
polynomial arithmetic, exact linear algebra, and algebraic lattices.

The organizing decision in this package is that a type verifies its axioms
when it is constructed. A `CyclicGroup` is a group, not a candidate group,
so every routine that consumes it can rely on associativity, an identity,
and inverses without re checking, and a structure that fails an axiom cannot
be built at all.

## Mathematical basis

A group is a set with an associative binary operation, an identity, and
inverses. Lagrange's theorem states that for a finite group $G$ and a
subgroup $H \leq G$,

$$|H| \text{ divides } |G|, \qquad [G : H] = \frac{|G|}{|H|},$$

so the subgroup orders of a group of order twelve can only be one, two,
three, four, six, or twelve. For a group action the orbit stabilizer theorem
states that for every element $x$ of the acted upon set,

$$|G| = |\mathrm{Orb}(x)| \cdot |\mathrm{Stab}(x)|,$$

which turns a counting problem about orbits into a counting problem about
stabilizers.

A ring adds a second operation, distributive over the first. A field is a
commutative ring in which every nonzero element is invertible, and a finite
field of order $q$ exists exactly when $q = p^n$ for a prime $p$ and a
positive integer $n$, in which case it is unique up to isomorphism. The
library constructs such fields and performs exact arithmetic in them.

## Module map

| Subpackage | Responsibility |
| --- | --- |
| `groups` | Group families, subgroups, morphisms, actions, Sylow theory |
| `rings` | Rings, ideals, units, zero divisors, characteristic, quotients |
| `fields` | Prime fields, finite and Galois fields, extensions |
| `polynomials` | Exact polynomial arithmetic, factorization, interpolation |
| `linear` | Exact linear algebra over the rationals and modular rings |
| `lattice` | Algebraic, modular, complemented, and Boolean lattices |

## Groups

### Families

| Type | Group |
| --- | --- |
| `CyclicGroup(n)` | The integers modulo n under addition |
| `SymmetricGroup(n)` | All permutations of n letters |
| `AlternatingGroup(n)` | The even permutations |
| `DihedralGroup(n)` | The symmetries of a regular n gon |
| `KleinGroup()` | The Klein four group |
| `QuaternionGroup()` | The quaternion group of order eight |
| `PermutationGroup(generators)` | The group generated by given permutations |
| `DirectProduct(left, right)` | The product group |

```python
>>> from discretus.algebra.groups import CyclicGroup, DihedralGroup, SymmetricGroup
>>> z6 = CyclicGroup(6)
>>> z6.order(), z6.is_abelian()
(6, True)
>>> z6.element_orders()
{0: 1, 1: 6, 2: 3, 3: 2, 4: 3, 5: 6}
>>> [h.order() for h in z6.subgroups()]
[1, 2, 3, 6]
>>> DihedralGroup(4).order(), SymmetricGroup(4).order()
(8, 24)
```

The subgroup orders divide the group order, which is Lagrange's theorem
appearing in the output. The search for subgroups uses the theorem rather
than merely respecting it: only divisors of the order need be considered,
which is what makes the search tractable.

### Structure

| Routine or method | Meaning |
| --- | --- |
| `subgroups()` | Every subgroup, up to the configured limit |
| `generated_by(elements)` | The subgroup a set generates |
| `is_subgroup(candidate)` | Whether a subset is a subgroup |
| `normal_subgroups()` | The normal subgroups |
| `is_normal(subgroup)` | Invariance under conjugation |
| `cosets(subgroup, side)` | Left or right cosets |
| `quotient_group(subgroup)` | The quotient by a normal subgroup |
| `center()` | The elements that commute with everything |
| `centralizer(element)`, `normalizer(subgroup)` | The usual subgroups |
| `conjugacy_classes()` | The classes |
| `commutator_subgroup()` | The derived subgroup |
| `sylow_subgroups(prime)` | The Sylow subgroups for a prime |
| `is_simple()`, `is_solvable()`, `is_cyclic()` | Structural predicates |
| `cayley_table()` | The table, rendered as text |
| `cayley_graph(generators=None)` | The Cayley graph, as a graph |

The Cayley graph is the clearest cross domain bridge in the library: a group
produces a graph, and every routine in
[`discretus.graphs`](graphs.md) then applies to it. The graph is connected
exactly when the chosen elements generate the group, its diameter is the
word length metric, and its automorphisms relate to the group's own.

### Morphisms and actions

| Routine or type | Meaning |
| --- | --- |
| `Homomorphism(source, target, mapping)` | A structure preserving map, verified |
| `is_homomorphism(source, target, mapping)` | The verification alone |
| `kernel(morphism)`, `image(morphism)` | The usual subgroups |
| `Isomorphism`, `are_isomorphic(left, right)` | Isomorphism and its test |
| `automorphism_group(group)` | The automorphisms |
| `GroupAction(group, points, action)` | An action, with the axioms verified |
| `orbit(action, point)`, `stabilizer(action, point)` | The orbit and the stabilizer |
| `orbits(action)` | Every orbit |
| `burnside_count(action)` | The orbit count by Burnside's lemma |

```python
>>> from discretus.algebra.groups import CyclicGroup, GroupAction
>>> rotation = GroupAction(
...     group=CyclicGroup(4),
...     points=[(i, j) for i in range(2) for j in range(2)],
...     action=lambda g, p: ((p[1], 1 - p[0]) if g % 2 else p),
... )
>>> len(rotation.orbits())
2
```

The orbit stabilizer theorem is asserted by the suite for every action it
constructs: the group order equals the orbit size times the stabilizer size,
for every point. That is a strong check, because it links three separately
computed quantities.

## Rings

| Type or routine | Meaning |
| --- | --- |
| `Ring(carrier, addition, multiplication)` | A ring, axioms verified |
| `CommutativeRing` | With commutative multiplication verified |
| `IntegralDomain` | With no zero divisors verified |
| `Zmod(n)` | The integers modulo n |
| `PolynomialRing(base, variable)` | Polynomials over a base ring |
| `QuotientRing(ring, ideal)` | The quotient by an ideal |
| `Ideal(ring, generators)` | The ideal a set generates |
| `units(ring)` | The invertible elements |
| `zero_divisors(ring)` | The zero divisors |
| `characteristic(ring)` | The additive order of the identity |
| `RingHomomorphism(source, target, mapping)` | A ring morphism, verified |

```python
>>> from discretus.algebra.rings import Zmod
>>> r = Zmod(12)
>>> r.units(), r.zero_divisors(), r.characteristic()
([1, 5, 7, 11], [2, 3, 4, 6, 8, 9, 10], 12)
>>> Zmod(7).is_field()
True
```

The two lists above partition the nonzero elements of the ring of integers
modulo twelve, which is the concrete content of the statement that an
element of such a ring is either a unit or a zero divisor. The ring is a
field exactly when the modulus is prime, which `is_field` decides and the
suite asserts against a primality test.

## Fields

| Type or routine | Meaning |
| --- | --- |
| `PrimeField(p)` | The field of integers modulo a prime |
| `FiniteField(p, n)` | The field of order p to the n |
| `GaloisField(p, n, modulus=None)` | The same, with an explicit modulus |
| `GF2(n)` | The binary field extension, with bitwise arithmetic |
| `RationalField()` | The rationals, as a field object |
| `FieldExtension(base, minimal_polynomial)` | A simple extension |
| `minimal_polynomial(element, base)` | The minimal polynomial of an element |
| `is_irreducible(polynomial, field)` | Irreducibility over a field |
| `primitive_element(field)` | A generator of the multiplicative group |

```python
>>> from discretus.algebra.fields import GaloisField, PrimeField
>>> f = PrimeField(7)
>>> f.inverse(3), f.order(), f.characteristic()
(5, 7, 7)
>>> gf = GaloisField(2, 3)
>>> gf.order(), gf.is_field()
(8, True)
>>> len(gf.multiplicative_group())
7
```

The multiplicative group of a finite field of order $q$ is cyclic of order
$q - 1$, which the library relies on when it searches for a primitive
element and which the suite asserts by checking that the reported element
has order exactly $q - 1$.

A field of order eight cannot be the integers modulo eight, because eight is
not prime, and the distinction is worth making concrete: `Zmod(8)` has zero
divisors and `GaloisField(2, 3)` does not, even though both have eight
elements. The package makes that comparison a two line experiment.

## Polynomials

| Routine or method | Meaning | Complexity |
| --- | --- | --- |
| `Polynomial(coefficients, variable)` | A dense exact polynomial | Construction O(n) |
| `add`, `subtract`, `multiply`, `scale` | Ring operations | O(n m) for products |
| `divmod` | Division with remainder | O((n - m + 1) m) |
| `gcd(left, right)` | The greatest common divisor | O(n m) |
| `extended_gcd(left, right)` | With Bezout cofactors | O(n m) |
| `evaluate(point)` | Horner evaluation | O(n) |
| `derivative()`, `antiderivative()` | Formal calculus | O(n) |
| `compose(other)` | Substitution | O(n m) |
| `factor()` | Factorization over the rationals or a finite field | Varies |
| `roots()` | Exact rational roots, and factors above degree one | O(divisors of the trailing term) |
| `resultant(other)` | The resultant | O(n m) |
| `interpolate(points)` | The Lagrange interpolant | O(n squared) |
| `cyclotomic(n)` | The nth cyclotomic polynomial | O(n log n) |

```python
>>> from discretus.algebra.polynomials import Polynomial, interpolate
>>> p, q = Polynomial([1, 0, -1]), Polynomial([1, 1])
>>> p, q, p * q
(Polynomial(-x^2 + 1), Polynomial(x + 1), Polynomial(-x^3 - x^2 + x + 1))
>>> divmod(p, q)
(Polynomial(-x + 1), Polynomial(0))
>>> p.roots()
[-1, 1]
>>> interpolate([(0, 1), (1, 3), (2, 7)]).to_text()
'x^2 + x + 1'
```

The interpolation is exact, so the polynomial through three points with
integer coordinates has rational coefficients that are the true ones rather
than a least squares approximation. That is what makes it usable for secret
sharing, for finite difference identities, and for the constructions in
coding theory that the finite field machinery supports.

Factorization over the rationals uses rational root extraction and then
factor combination; over a finite field it uses the standard square free,
distinct degree, and equal degree decomposition. The docstrings say which
algorithm runs in which setting, because the two have very different costs.

## Exact linear algebra

| Routine or type | Meaning | Complexity |
| --- | --- | --- |
| `Vector(entries)` | An exact vector | O(n) |
| `Matrix(rows)` | An exact matrix | O(n m) |
| `determinant(matrix)` | By fraction free elimination | O(n cubed) |
| `gaussian_elimination(matrix)` | Row echelon form, with the operations recorded | O(n cubed) |
| `rank(matrix)` | The rank | O(n cubed) |
| `inverse(matrix)` | The inverse, or an error when singular | O(n cubed) |
| `lu_decomposition(matrix)` | The factorization, with permutations | O(n cubed) |
| `solve(matrix, vector)` | The solution set of a linear system | O(n cubed) |
| `eigenvalues(matrix)` | Exact where the characteristic polynomial factors | O(n cubed) plus factoring |
| `characteristic_polynomial(matrix)` | The polynomial | O(n cubed) |
| `BooleanMatrix(rows)` | A matrix over the Boolean semiring | O(n m) |
| `ModularMatrix(rows, modulus)` | A matrix over a modular ring | O(n m) |

```python
>>> from discretus.algebra.linear import Matrix, determinant, rank
>>> m = Matrix([[2, 1], [1, 1]])
>>> determinant(m), rank(m)
(1, 2)
>>> m.inverse()
Matrix([[1, -1], [-1, 2]])
```

Everything here is exact, which is the reason the package exists: a rank
computed in floating point is a guess about whether a pivot is zero, and a
rank computed over the rationals is a fact. The elimination is fraction
free where that is possible, which keeps the intermediate numerators from
growing as fast as naive rational elimination would.

`BooleanMatrix` is the representation the relation and graph packages use
for reachability, where multiplication is composition and the transitive
closure is the closure of the matrix. `ModularMatrix` is what finite field
linear algebra runs on, and it is what makes coding theory examples
possible.

## Lattices

| Type | Meaning |
| --- | --- |
| `AlgebraicLattice(carrier, meet, join)` | A lattice given by its operations, axioms verified |
| `ModularLattice` | With the modular law verified |
| `ComplementedLattice` | With complements verified to exist |
| `BooleanAlgebra(carrier, ...)` | A complemented distributive lattice |

The algebraic view of a lattice, as a set with two idempotent, commutative,
associative operations satisfying the absorption laws, is equivalent to the
order theoretic view in [`discretus.sets`](sets.md), and the library
provides both together with the conversion between them. Verifying the
absorption laws is what the type does on construction, and the equivalence
with the order view is asserted in the suite, which is the cleanest possible
statement that the two definitions agree.

A Boolean algebra is the structure behind propositional logic, and the
package makes the connection explicit: the truth values under conjunction,
disjunction, and negation form a Boolean algebra, the subsets of a set under
intersection, union, and complement form another, and the two are isomorphic
when the set has one element.

## Worked example: verifying Lagrange and orbit stabilizer

The two theorems this package leans on hardest are Lagrange's theorem and
the orbit stabilizer theorem, and both are checkable on small groups. The
following is close to what the suite asserts.

```python
from discretus.algebra.groups import (
    AlternatingGroup,
    CyclicGroup,
    DihedralGroup,
    DirectProduct,
    KleinGroup,
    QuaternionGroup,
    SymmetricGroup,
)

groups = [
    CyclicGroup(6),
    CyclicGroup(12),
    KleinGroup(),
    DihedralGroup(4),
    DihedralGroup(6),
    SymmetricGroup(3),
    SymmetricGroup(4),
    AlternatingGroup(4),
    QuaternionGroup(),
    DirectProduct(CyclicGroup(2), CyclicGroup(3)),
]

for group in groups:
    order = group.order()

    # Lagrange: every subgroup order divides the group order.
    for subgroup in group.subgroups():
        assert order % subgroup.order() == 0
        assert order // subgroup.order() == group.index_of(subgroup)

    # Every element order divides the group order, which is the corollary.
    for element, element_order in group.element_orders().items():
        assert order % element_order == 0
        assert group.power(element, order) == group.identity()

    # The cosets of a subgroup partition the group.
    for subgroup in group.subgroups():
        cosets = group.cosets(subgroup, side="left")
        assert len(cosets) * subgroup.order() == order
        flattened = [element for coset in cosets for element in coset]
        assert sorted(flattened) == sorted(group.elements())

    # The conjugacy classes partition the group, and their sizes divide it.
    classes = group.conjugacy_classes()
    assert sum(len(cls) for cls in classes) == order
    for cls in classes:
        assert order % len(cls) == 0

    # The centre is a normal subgroup, and a group is abelian exactly when
    # it is the whole group.
    centre = group.center()
    assert group.is_normal(centre)
    assert (centre.order() == order) == group.is_abelian()

print("Lagrange and its corollaries hold for ten groups")
```

Now the orbit stabilizer theorem, on the natural action of a symmetric group
on the subsets of its letters.

```python
from itertools import combinations

from discretus.algebra.groups import GroupAction, SymmetricGroup

group = SymmetricGroup(4)
points = [frozenset(c) for size in range(5) for c in combinations(range(4), size)]


def relabel(permutation, subset):
    return frozenset(permutation[i] for i in subset)


action = GroupAction(group=group, points=points, action=relabel)

for point in points:
    orbit = action.orbit(point)
    stabilizer = action.stabilizer(point)
    assert group.order() == len(orbit) * stabilizer.order()

# The orbits are exactly the subsets of a given size, which is the content
# of the action being the natural one.
assert sorted(len(orbit) for orbit in action.orbits()) == [1, 1, 4, 4, 6]

# Burnside counts the orbits as the average fixed point count.
assert action.burnside_count() == len(action.orbits())

print("the orbit stabilizer theorem holds for every subset of four letters")
```

Both examples follow the same discipline: state the theorem as an assertion,
run it over every structure the package can build cheaply, and let a failure
point at the routine that disagrees with the mathematics. Because the
quantities involved are computed by separate routines, an agreement is
strong evidence and a disagreement localizes the defect to one of them.

## Complexity summary

| Operation | Complexity |
| --- | --- |
| Group axiom verification | O(n cubed) for associativity |
| Element order | O(n) operations |
| Subgroup enumeration | Exponential in general, pruned by Lagrange |
| Coset decomposition | O(n) per coset |
| Conjugacy classes | O(n squared) |
| Sylow subgroups | Exponential in general |
| Cayley table | O(n squared) |
| Orbit and stabilizer | O(group order times point count) |
| Ring axiom verification | O(n cubed) for distributivity |
| Finite field arithmetic | O(degree squared) per multiplication |
| Polynomial multiplication | O(n m) |
| Polynomial division | O((n - m + 1) m) |
| Polynomial greatest common divisor | O(n m) |
| Determinant, rank, inverse | O(n cubed) exact operations |

The cubic verification costs are why the types accept a flag to skip
verification. It is off by default, because a structure that silently fails
its axioms produces wrong answers everywhere downstream, and it exists for
the case where a caller has already established the axioms and is
constructing many structures in a loop.

## Errors

| Exception | Raised when |
| --- | --- |
| `AxiomViolationError` | A candidate structure fails an axiom, naming it and a counterexample |
| `DomainError` | An element is outside the carrier, or a modulus or order is invalid |
| `DimensionError` | Matrix or vector shapes disagree |
| `InfeasibleError` | No inverse, no primitive element, a singular matrix, or a field of the requested order does not exist |
| `ValidationError` | A malformed table, or a polynomial given a non numeric coefficient |
| `LimitExceededError` | A subgroup or element enumeration exceeded the configured limit |

Asking for a field of order six raises `InfeasibleError`, because six is not
a prime power and no such field exists. That is the right answer, and the
message says why.

## Design notes

**Axioms are verified at construction.** The cost is paid once and the
benefit applies to every later routine. A type that promised its axioms
without checking them would push the check into every consumer or, worse,
into none of them.

**Elements are values, not wrappers.** A cyclic group's elements are plain
integers and a symmetric group's are tuples, so they print readably, compare
naturally, and can be used outside the group. The `Labeled` wrapper in
`discretus.core.element` exists for the cases where a display name is wanted
without changing identity.

**Operations come from the core layer.** Every structure here is built on
`discretus.core.operation.BinaryOperation` and the hierarchy in
`algebraic_base`, so associativity means the same thing for a group, a ring,
and a lattice, and it is implemented once.

**Two views of a lattice, one implementation of each law.** The order
theoretic lattice lives in the set package and the algebraic one lives here,
and the conversion between them is explicit. Neither is treated as the real
one.
